def make_design_matrix(x, degree, basis):
    """
    Tworzy macierz cech wielomianowych.

    x      : wektor 1D
    degree : maksymalny stopień wielomianu
    basis  : nazwa bazy
    """
    x = np.asarray(x).ravel()

    if basis == "monomial":
        return polyvander(x, degree)

    if basis == "chebyshev":
        return chebvander(x, degree)

    if basis == "legendre":
        return legvander(x, degree)

    if basis == "hermite":
        return hermvander(x, degree)

    if basis == "laguerre":
        # Laguerre jest naturalny dla x >= 0.
        # Ponieważ dane mamy w [-1, 1], mapujemy je do [0, 1].
        x01 = (x + 1.0) / 2.0
        return lagvander(x01, degree)

    raise ValueError(f"Nieznana baza: {basis}")


def make_model(regularizer, alpha=1e-3, l1_ratio=0.5):
    """
    Zwraca model regresyjny zgodny z wybranym regularyzatorem.
    """
    if regularizer == "least_squares":
        return LinearRegression()

    if regularizer == "ridge":
        return Ridge(alpha=alpha)

    if regularizer == "lasso":
        return Lasso(alpha=alpha, max_iter=50000)

    if regularizer == "elasticnet":
        return ElasticNet(alpha=alpha, l1_ratio=l1_ratio, max_iter=50000)

    raise ValueError(f"Nieznany regularyzator: {regularizer}")


def count_nonzero_coefficients(model, tol=1e-10):
    """
    Liczy niezerowe współczynniki.
    Dla Lasso/ElasticNet pokazuje sparsity.
    """
    if not hasattr(model, "coef_"):
        return np.nan

    coef = np.asarray(model.coef_).ravel()
    return int(np.sum(np.abs(coef) > tol))

CZĘŚĆ 1 — regresja w bazach wielomianowych¶

Dane:

[ y = \sin(2\pi x) + \epsilon ]

gdzie:

[ \epsilon \sim \mathcal{N}(0, \sigma^2) ]

W tej części obserwujemy:

  • train error,
  • test error,
  • okolice progu interpolacji,
  • wpływ bazy wielomianowej,
  • wpływ regularyzatora.

# ============================================================
# EKSPERYMENT REGRESYJNY
# ============================================================

degrees = list(range(1, MAX_DEGREE + 1))

train_mse = []
test_mse = []
nonzero_coefs = []
condition_numbers = []

start = time.time()

for d in degrees:

    X_train = make_design_matrix(x_train, d, POLY_BASIS)
    X_test = make_design_matrix(x_test, d, POLY_BASIS)

    condition_numbers.append(np.linalg.cond(X_train))

    if SCALE_FEATURES:
        scaler = StandardScaler()
        X_train_used = scaler.fit_transform(X_train)
        X_test_used = scaler.transform(X_test)
    else:
        X_train_used = X_train
        X_test_used = X_test

    model = make_model(
        REGULARIZER,
        alpha=ALPHA,
        l1_ratio=L1_RATIO
    )

    model.fit(X_train_used, y_train)

    pred_train = model.predict(X_train_used)
    pred_test = model.predict(X_test_used)

    train_mse.append(mean_squared_error(y_train, pred_train))
    test_mse.append(mean_squared_error(y_test, pred_test))
    nonzero_coefs.append(count_nonzero_coefficients(model))

elapsed = time.time() - start

print(f"Baza: {POLY_BASIS}")
print(f"Regularyzator: {REGULARIZER}")
print(f"Alpha: {ALPHA}")
print(f"Czas: {elapsed:.2f} s")

Czas: 0.07 s

CZĘŚĆ 2 — sieć neuronowa¶

Ta część jest celowo oddzielona od regresji wielomianowej.
Sieć nadal rozwiązuje problem regresji, ale dostaje trudniejsze dane niż część wielomianowa.

Celem nie jest uzyskanie idealnego wykresu z podręcznika, tylko obserwacja:

  • przejścia od underfittingu do overparameterization,
  • wpływu szumu i uszkodzonych etykiet,
  • różnicy między train error i test error,
  • roli optimizera i weight decay.

Sieć:

1 → width → width → 1

Zmieniamy width, a więc liczbę parametrów.

  • modelem zbyt małym,
  • modelem bliskim interpolacji,

class SmallNet(nn.Module):

    def __init__(self, width):

        super().__init__()

        self.net = nn.Sequential(
            nn.Linear(1, width),
            nn.Tanh(),
            nn.Linear(width, width),
            nn.Tanh(),
            nn.Linear(width, 1)
        )

    def forward(self, x):
        return self.net(x)


def count_params(model):
    return sum(p.numel() for p in model.parameters())

ODPOWIEDZI NA TE PYTANIA wymagają odniesienia do konkretnych wykresów z notebooka.¶

Odpowiedzi¶

Ad 1. Interpolation peak jest przede wszystkim zjawiskiem statystycznym, a nie numerycznym. Widać to po tym, że niezależnie od wyboru bazy wielomianu interpolation peak występuje w każdej z tych metod w okolicy p ~= n. Wybór bazy i regularyzacji wpływa na to jak duży będzie ten peak oraz jak stabilny numerycznie będzie model, ale nie ma wpływu na samo pojawienie się tego zjawiska. Problemy numeryczne mogą jednak dodatkowo pogarszać wyniki. Dla niektórych baz pojawiają się niestabilności związane z błędami interpolacji oraz efektem Rungego, jednak nie jest to główny powód występowania interpolation peak, ponieważ zjawisko to nadal pojawia się również dla bardziej stabilnych baz i przy zastosowaniu regularyzacji.

Ad 2. Model bliski interpolation threshold posiada zbliżoną liczbę parametrów do liczby próbek (p ~= n), przez co znajduje się na granicy interpolacji danych treningowych. Jest to problem ponieważ model ten dopasowuje się idealnie do danych treningowych, a więc także do szumu który w nich występuje. Przez co następuje bardzo duży overfitting, co jak widać na wykresach z tego ćwiczenia powoduje, że model o p ~= n wykazuje największe MSE spośród wszystkich testowanych modeli (na danych testowych). Z drugiej strony model z p >> n również jest w stanie idealnie dopasować dane treningowe, jednak posiada znacznie większą przestrzeń możliwych rozwiązań. Dzięki użyciu SGD model jest w stanie znaleźć funkcję która generalizuje dane lepiej niż model bliski interpolation threshold, co prowadzi do mniejszego błędu na danych testowych mimo znacznie większej liczby parametrów.
